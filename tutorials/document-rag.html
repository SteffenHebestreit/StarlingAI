📚 Document RAG

Attach a document, ask about it — the swarm extracts, indexes, and answers from the source automatically.

What is Document RAG?

Document RAG (retrieval-augmented generation) lets StarlingAI answer from the contents of files you attach to a conversation — PDFs, Word/PowerPoint/Excel documents, images, Markdown, and more — without stuffing the whole file into the prompt. Files are converted to text, indexed into a knowledge graph, and the most relevant excerpts are retrieved and injected as context on every turn.

It is powered by engram, a graph-RAG service: each document is chunked, summarised and keyword-tagged by the LLM, embedded across multiple channels, and linked in engram's in-process (engramdb) graph. Search runs a HyDE → multi-channel retrieval → fusion → graph-expansion → cross-encoder rerank pipeline, so retrieval is far sharper than plain vector similarity.

How it works
  1. Extract. A file attached to your message is converted to Markdown by the file-conversion service (the fastapi-mcp-template running file_to_markdown, with OCR/vision fallback for images).
  2. Ingest. The text is sent to engram and tagged with a scope — by default session:<id>, so it is only visible inside that conversation. engram chunks it, extracts a summary + keywords, builds embeddings, and stores the graph. Re-attaching the same file is idempotent (deduped by content hash).
  3. Retrieve. Before answering, the runtime searches engram for the most relevant excerpts within your active scope and injects them as hidden context. It also exposes the search_documents, list_documents, ingest_document, and forget_document tools for explicit control.
  4. Answer. The assistant responds using the retrieved excerpts and cites the document name.
Services it runs

Document RAG is opt-in: it lives behind the rag compose profile (off by default), so a plain sai start / docker compose up does not start engram or the reranker. Enable it with sai start --rag (or set SAI_ENABLE_RAG=1 in .env to persist it). The stack adds two containers:

  • engram — the graph-RAG API (port 8088). It stores its graph in-process via the embedded engramdb backend (in-process vector + BM25 + native-adjacency graph, no separate graph DB). Its embeddings and extraction LLM point at the same LM Studio endpoint as the gateway (SAI_PRIMARY_MODEL_URL), using the loaded text-embedding-qwen3-embedding-0.6b (1024-dim) and chat models.
  • reranker — a GPU-first (fp16, ~1.4 GB) custom sentence-transformers CrossEncoder sidecar serving Qwen/Qwen3-Reranker-0.6B in the TEI /rerank wire format, falling back to CPU when no GPU is present. It powers both engram's rerank stage and the gateway's own retrieval reranker. The model downloads from HuggingFace on first request.

The gateway degrades gracefully if these services are absent — Document RAG simply turns into a no-op.

Configuring it

Open Settings → Document RAG in the dashboard, or edit retrieval.documentRag in starlingai.json: 

"retrieval": {
  "reranker": {
    "enabled": true,
    "mode": "tei",
    "baseUrl": "http://reranker:80",
    "model": "BAAI/bge-reranker-v2-m3"
  },
  "documentRag": {
    "enabled": true,
    "engramBaseUrl": "http://engram:8088",
    "autoIngestAttachments": true,   // index files attached to a turn automatically
    "injectContext": true,           // retrieve + inject excerpts before answering
    "retrievalTopK": 6,              // excerpts injected per turn
    "maxContextChars": 6000,
    "includeUserDocs": false,        // also search the user's personal library
    "includeWorkspaceDocs": false,   // also search the workspace-shared library
    "workspaceName": "workspace"
  }
}

Changes saved from Settings take effect immediately — no restart needed.

Scopes: session, user, and workspace

Every document is stored under a scope token, and retrieval only sees documents in your active scope:

  • Session (always on) — documents attached to a conversation are searchable only within that conversation.
  • User (includeUserDocs) — also search a personal library shared across the signed-in user's conversations.
  • Workspace (includeWorkspaceDocs) — also search a library shared across the whole workspace.

To put a document into the user or workspace library, ask an agent to ingest_document with the matching scope, e.g. "ingest reports/q3.pdf into the workspace library".

Try it
  1. Confirm the services are healthy: docker compose --profile rag ps engram reranker.
  2. In the dashboard chat, attach a PDF or DOCX and ask a specific question about its contents.
  3. The first turn extracts + indexes the file (a few seconds), then answers from it. Follow-up questions reuse the index instantly.
  4. Ask "what documents are available?" to have the assistant call list_documents.
Tips & gotchas
  • Reranker first-start lag. The sidecar downloads Qwen/Qwen3-Reranker-0.6B on first run. Until it is ready, engram still works — it falls back to its fused score for ranking.
  • LM Studio JSON mode. engram's metadata extraction uses the LLM; LM Studio rejects response_format=json_object, so ENGRAM_LLM_JSON_MODE defaults to false (engram parses JSON out of the plain reply).
  • Point engram at the right LM Studio. engram's embedding/LLM endpoints default to the gateway's SAI_PRIMARY_MODEL_URL — the instance with the models loaded — not host.docker.internal.
  • Lightweight alternative. For one-off large pasted text (not a file), the rag_ingest/rag_search tools offer a simpler pgvector-backed store without the engram graph pipeline.
