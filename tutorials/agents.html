🤖 Agents

StarlingAI ships 25+ specialist agents. The swarm automatically discovers and routes to the right one — like starlings self-organizing without a conductor.

How the swarm routes tasks

You never need to address agents directly. Simply send a message — the swarm analyses it, searches for the best matching specialist using hybrid semantic + outcome-weighted scoring, delegates the task, and returns the result. If the first agent fails, the swarm automatically falls back to the next-best candidate — self-healing without human intervention.

This is the swarm's emergent execution: each delegation improves future routing through outcome tracking. The swarm gets smarter over time, learning which specialists handle which tasks best.

Changing a model for an agent

Via the dashboard

  1. Open http://localhost:3001
  2. Go to Settings → Sub-Agents
  3. Click the agent you want to change
  4. Update the Primary model and optionally the Fallback model fields
  5. Click Save

Via starlingai.json

json
{
  "subAgents": {
    "researcher": {
      "model": {
        "primary": "qwen/qwen3.5-35b-a3b",
        "fallback": "qwen/qwen3.5-9b"
      }
    },
    "summarizer": {
      "model": {
        "primary": "qwen/qwen3.5-9b"
      }
    }
  }
}
ℹ️
After changing starlingai.json, restart the gateway: docker compose restart gateway
Embedding model (better routing)

By default the orchestrator uses keyword matching to route queries. Installing a dedicated embedding model in LM Studio enables semantic search — significantly improving routing accuracy.

Recommended embedding model

Search for text-embedding-qwen3-embedding-8b in LM Studio's Discover tab, download it, and load it alongside your main model. Then update your config:

json
{
  "agents": {
    "defaults": {
      "model": {
        "embeddingModel": "text-embedding-qwen3-embedding-8b",
        "embeddingUrl": "http://host.docker.internal:1234/v1"
      }
    }
  }
}
Running evaluations

StarlingAI ships with an evaluation harness. Run it to benchmark agent quality and routing accuracy using your own test cases.

Using the canonical eval file

bash
pnpm --filter @starlingai/core agents:evaluate

Writing your own evals

Copy the canonical file and add your own test cases:

bash
cp agent-eval.jsonc my-evals.jsonc
# Edit my-evals.jsonc, then:
pnpm --filter @starlingai/core agents:evaluate my-evals.jsonc
jsonc
// my-evals.jsonc
{
  "workspacePath": "/workspace",
  "cases": [
    {
      "name": "research-docs",
      "agentName": "researcher",
      "task": "Summarise the LM Studio function calling requirements.",
      "expectIncludes": ["LM Studio"],
      "expectExcludes": ["Sub-agent error:"],
      "maxDurationMs": 45000
    },
    {
      "name": "coder-smoke",
      "agentName": "coder",
      "task": "Write a Python function to parse ISO dates.",
      "expectIncludes": ["def"],
      "expectExcludes": ["Sub-agent error:"],
      "maxDurationMs": 30000
    }
  ]
}

The evaluator prints pass/fail summaries, case previews, and can compare the run against a saved baseline.
