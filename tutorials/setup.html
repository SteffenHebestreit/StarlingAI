Prerequisites Done

Install the required tools before anything else. Click each tab for your operating system.

Node.js 22+

brew install node@22

Download and install from docker.com/products/docker-desktop. Make sure it's running before continuing.

pnpm

bash
npm install -g pnpm

LM Studio

Download from lmstudio.ai — available for macOS, Windows, and Linux. You'll configure it in the next step.

bash
node --version    # should print v22.x.x or higher

pnpm --version    # should print 9.x or higher
2
LM Studio Setup Done

StarlingAI uses LM Studio to run language models locally. The orchestrator needs a model with strong instruction-following and function-calling support.

Recommended models

ModelVRAMNotes
qwen/qwen3.5-35b-a3b ~20 GB Best quality — recommended for orchestrator
qwen/qwen3.5-4b ~4-5 GB Use if VRAM is limited (slightly lower quality)

How to load the model

  1. Open LM Studio
  2. Go to the Discover tab and search for qwen3.5
  3. Download your chosen model
  4. Go to Developer (the <> icon in the sidebar)
  5. Select the model from the dropdown at the top
  6. Enable Function Calling in the model settings
  7. Click Start Server
🖥
Screenshot: LM Studio → Developer → Start Server
The server starts on port 1234 by default
ℹ️
Keep LM Studio open and the server running while using StarlingAI. The gateway container connects to it via http://host.docker.internal:1234/v1.

Verify the server is running

bash
curl http://localhost:1234/v1/models
url
http://localhost:1234/v1/models

You should get a JSON response listing the loaded model.

3
Clone & Configure Done

Clone the repository

bash
git clone https://github.com/your-org/starlingai.git
cd starlingai

Copy the config template

bash
cp starlingai.example.json starlingai.json

Run the setup script

bash
node scripts/setup.mjs

The setup script does the following:

  • Generates a secure SAI_MASTER_KEY (AES-256 key for credential encryption)
  • Generates a SAI_JWT_SECRET for dashboard token signing
  • Generates a POSTGRES_PASSWORD
  • Writes all secrets to a .env file (never commit this file)

Key .env variables

.env
# Auto-generated by setup.mjs — do not edit manually
SAI_MASTER_KEY=<32-byte hex key>
SAI_JWT_SECRET=<long random string>
POSTGRES_PASSWORD=<random password>

# Optional — add channel tokens here or via the dashboard
TELEGRAM_BOT_TOKEN=
ANTHROPIC_API_KEY=

# Logging
LOG_LEVEL=info
⚠️
Never commit your .env file. It is listed in .gitignore by default. The SAI_MASTER_KEY encrypts all stored credentials — losing it means losing access to your stored channel secrets.
4
Install & Build Done

Install Node dependencies

bash
pnpm install

Build and start all services

bash
./start.sh
cmd
start.bat

The start script builds Docker images, starts all containers, waits for health checks, and prints a dashboard login token. First build takes 5–10 minutes (downloads base images and model weights).

ℹ️
Useful flags:
./start.sh --build — force rebuild
./start.sh --no-cache — rebuild with no Docker cache
./start.sh --fresh — wipe volumes + rebuild (clean slate)
./start.sh --pentest — also start the Kali pentest service
./start.sh --down — stop all services

What each container does

ContainerPortPurpose
gateway8765Core engine — WebSocket API, agent orchestration, channel adapters
web3001Dashboard UI for managing agents, scenes, and channels
postgresinternalPersistent storage for audit logs and configuration
redisinternalSession cache, rate limiting, and inter-service pub/sub
qwen3-asr-serviceinternalSpeech-to-text — Qwen3-ASR (downloads model on first start)
qwen3-tts-serviceinternalText-to-speech with voice cloning — Qwen3-TTS
fastapi-mcp-templateinternalFile-to-Markdown conversion (MCP tool)
tutorials3002This documentation site

Optional services

These run under separate profiles and can be added to a running stack at any time:

bash
# Start / stop optional services without restarting the core stack:
./extras.sh pentest on     # Kali Linux pentest toolchain
./extras.sh image on       # FLUX image generation
./extras.sh all on         # both
./extras.sh status         # show what's running

Check all containers are healthy

bash
docker compose ps

All services should show healthy or running status.

View logs

bash
# All services
docker compose logs -f

# Just the gateway
docker compose logs -f gateway

First Login Done

The dashboard uses token-based auth. Generate your first token with the included script.

Generate a login token

bash
./scripts/gen-token.sh
cmd
scripts\gen-token.bat

The script prints a JWT token to your terminal. Copy the entire token string.

Open the dashboard

url
http://localhost:3001

Paste the token into the login screen when prompted.

git pull
./start.sh --build

# Full clean rebuild with no cache

# Start with Kali pentest service
./start.sh --pentest

# Manage optional services on a running stack
./extras.sh pentest on
./extras.sh image on
./extras.sh status

# Restart a single container
docker compose restart gateway
