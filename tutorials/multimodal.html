🎙️ Multimodal Tools

Audio transcription, speech synthesis, image analysis, and document extraction — all backed by local or remote services.

What are multimodal tools?

StarlingAI agents can go beyond text. The multimodal tool suite gives your swarm the ability to hear (transcribe audio), speak (synthesize speech), see (analyse images), and read documents (convert files to text) — all without leaving your self-hosted stack.

These tools are available to any agent that is granted them in starlingai.json. Three pre-configured specialists — media_analyst, transcription_agent, and voice_narrator — are included in the default agent catalog and can be used immediately once the services they depend on are configured.

💡
All multimodal services are optional. Each tool falls back gracefully — returning a clear error — if the service it needs is not configured. The rest of the swarm continues to work normally.
Tool reference
Tool What it does Requires
transcribe_audio Converts an audio file (WAV, MP3, OGG, …) to text using an STT service multimodal.stt.baseUrl
list_tts_voices Returns available voices from the TTS service multimodal.tts.baseUrl
synthesize_speech Converts text to an audio file using a TTS service and saves it locally multimodal.tts.baseUrl
analyse_image Answers questions about an image using a vision-capable LLM multimodal.files.visionModel
extract_file_content Converts documents (PDF, DOCX, XLSX, …) to Markdown text multimodal.files.baseUrl or MCP server
Configuration

Add a multimodal block to your starlingai.json. Every sub-block is optional — leave out what you don't need.

json5
{
  "multimodal": {
    // Speech-to-text (Qwen3-ASR service)
    "stt": {
      "baseUrl": "http://host.docker.internal:5002",
      "model": "Qwen/Qwen3-ASR-1.7B"
    },
    // Text-to-speech (Qwen3-TTS service)
    "tts": {
      "baseUrl": "http://host.docker.internal:5004",
      "model": "Qwen/Qwen3-TTS-12Hz-0.6B-Instruct",
      "defaultLanguage": "English",
      "defaultSpeaker": "Vivian"
    },
    // File-to-Markdown conversion
    "files": {
      "baseUrl": "http://fastapi-mcp-template:8000",
      "visionModel": "lmstudio/Qwen/Qwen2.5-VL-7B-Instruct",
      "visionBaseUrl": "http://host.docker.internal:1234/v1",
      // OR use an MCP server instead of the REST service:
      "mcpServer": "file_converter"
    }
  }
}
ℹ️
Configuration can also be updated live from the dashboard under Settings → Multimodal. Changes take effect without a restart.
Speech-to-text (STT)

The transcribe_audio tool POSTs an audio file to the configured Qwen3-ASR endpoint. StarlingAI first tries the OpenAI-style /v1/audio/transcriptions route and falls back to Qwen3-ASR's native /transcribe route when needed.

Quick start with Qwen3-ASR

The Docker Compose stack includes a dedicated Qwen3-ASR container. To start just the STT service:

bash
# Start the Qwen3-ASR server on port 5002
docker compose up -d qwen3-asr-service

# Verify it is reachable
curl http://localhost:5002/health

Example — transcribing a file

json
// Agent tool call
{
  "tool": "transcribe_audio",
  "input": {
    "filePath": "/workspace/recordings/meeting_2026-03-17.wav",
    "language": "en"
  }
}

// Result
{
  "text": "Good morning everyone. Let's get started with the sprint review...",
  "segments": [
    { "start": 0.0, "end": 3.2, "text": "Good morning everyone." },
    { "start": 3.2, "end": 6.8, "text": "Let's get started with the sprint review." }
  ]
}

Using the transcription_agent

The pre-built specialist handles the full workflow — transcribing and saving the result to /workspace/transcripts/:

text
Transcribe /workspace/recordings/meeting_2026-03-17.wav and save a clean transcript.
Text-to-speech (TTS)

The synthesize_speech tool sends text to a TTS REST API and saves the returned audio as a WAV file. The default self-hosted option in this stack is Qwen3-TTS, with built-in speakers, saved voices, and voice cloning.

Quick start with Qwen3-TTS

bash
# Start Qwen3-TTS on port 5004
docker compose up -d qwen3-tts-service

# List saved voices
curl http://localhost:5004/voices

Example — generating speech

json
// Agent tool call
{
  "tool": "synthesize_speech",
  "input": {
    "text": "Your weekly digest is ready. Here are the top five stories.",
    "speaker": "Vivian",
    "outputPath": "/workspace/audio/digest.wav"
  }
}

// Result
{
  "filePath": "/workspace/audio/digest.wav",
  "speaker": "Vivian",
  "durationSeconds": 4.2
}

Choosing a voice

Ask the voice_narrator agent to list voices and pick the best one for your content:

text
Read out the following article in a calm, professional voice and save it as /workspace/audio/article.wav:

[article text here]
Image analysis

The analyse_image tool passes an image (file path or URL) and a question to a vision-capable LLM model. The model is configured through multimodal.files.visionModel; it must be loaded in LM Studio or another provider that accepts OpenAI-compatible vision requests.

Supported input formats

  • JPEG, PNG, WebP, GIF (first frame)
  • Local file path — /workspace/screenshots/ui.png
  • HTTP/HTTPS URL (fetched server-side)

Example — UI screenshot analysis

json
// Agent tool call
{
  "tool": "analyse_image",
  "input": {
    "imagePath": "/workspace/screenshots/dashboard.png",
    "question": "List every UI element visible and note any error states."
  }
}

// Result
{
  "answer": "The screenshot shows a navigation sidebar on the left with 5 items: Overview, Agents, Scenes, Channels, and Settings. The main area displays an error banner in red reading 'Connection timeout'. Below it is a table with 3 rows..."
}

Using the media_analyst

text
Analyse the chart in /workspace/exports/q1-results.png and extract the revenue figures for each month.
Document extraction

The extract_file_content tool converts binary documents to readable Markdown text. It can be backed either by a REST service (e.g. MarkItDown, Docling) or by a MCP server that exposes a convert_to_markdown tool.

Supported file types

FormatNotes
PDFText extraction; image-heavy PDFs may need vision model for full content
DOCX / DOCFull paragraph, heading, and table extraction
XLSX / XLSConverts each sheet to a Markdown table
PPTXExtracts slide text and notes
HTMLStrips tags and extracts readable content
CSVConverts to Markdown table (first 500 rows)

Example

json
// Agent tool call
{
  "tool": "extract_file_content",
  "input": {
    "filePath": "/workspace/docs/contract_v3.pdf"
  }
}

// Result
{
  "content": "# Service Agreement\n\n## 1. Parties\n\nThis agreement is between...",
  "mimeType": "application/pdf",
  "pageCount": 12
}

Configuring an MCP server

If you prefer to use an MCP tool instead of a REST endpoint:

json5
{
  "multimodal": {
    "files": {
      // Set mcpServer to the MCP server name (no baseUrl needed)
      "mcpServer": "file_converter"
    }
  },
  "mcp": {
    "servers": {
      "file_converter": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"]
      }
    }
  }
}
Browser tools

Seven Playwright-based tools are available through the MCP Playwright integration. They give agents the ability to drive a real browser — navigating pages, clicking elements, filling forms, and capturing screenshots.

Tool What it does
mcp__playwright__browser_navigateNavigate to a URL
mcp__playwright__browser_snapshotCapture accessibility snapshot of the current page
mcp__playwright__browser_screenshotSave a PNG screenshot
mcp__playwright__browser_clickClick an element by selector or text
mcp__playwright__browser_typeType text into an input field
mcp__playwright__browser_selectSelect a dropdown option
mcp__playwright__browser_wait_forWait for a selector or URL pattern

Enabling Playwright MCP

json5
{
  "mcp": {
    "servers": {
      "playwright": {
        "command": "npx",
        "args": ["-y", "@playwright/mcp@latest"]
      }
    }
  }
}
⚠️
Browser tools run in the gateway process, not inside the Docker sandbox. Agents that use them should be granted only the minimum set of browser tools they need — do not grant all seven unless the agent genuinely requires full browser control.
Gateway API routes

The gateway exposes REST endpoints for direct multimodal access without going through the agent runtime:

MethodPathDescription
GET/api/multimodal/configRead current multimodal configuration
PUT/api/multimodal/configUpdate multimodal configuration live
GET/api/multimodal/statusHealth check for all multimodal services
POST/api/tools/file_to_markdownConvert uploaded file to Markdown
POST/api/multimodal/transcribeTranscribe an uploaded audio file
GET/api/multimodal/voicesList saved voices, built-in speakers, and TTS models
POST/api/multimodal/voices/saveUpload a reusable voice sample to Qwen3-TTS
POST/api/multimodal/ttsSynthesize speech from text

Example — checking service health

bash
curl -H "Authorization: Bearer $SAI_TOKEN" \
  http://localhost:8765/api/multimodal/status
json
{
  "stt":   { "ok": true },
  "tts":   { "ok": true },
  "files": { "ok": false, "error": "Service unreachable at http://localhost:7700" }
}
Tips & best practices
  • Use the built-in specialists first. The media_analyst, transcription_agent, and voice_narrator agents are pre-configured with the right tool grants and system prompts. Grant them to scenes rather than writing custom agents unless your use-case is genuinely different.
  • Keep audio files on the workspace volume. Agents running inside Docker containers can only access paths under /workspace. Make sure your audio and image files are mounted there.
  • Vision queries are model-dependent. The quality of analyse_image results depends entirely on the vision model you have loaded. Qwen3.5-35B is vision-enabled and works well for general-purpose visual QA without requiring a separate vision model.
  • Large documents may need chunking. extract_file_content returns the full document text. For very large PDFs, ask the media_analyst to summarise or extract specific sections rather than returning everything at once.
  • Check service health before running scenes. Query /api/multimodal/status to confirm that all services your scene depends on are reachable before triggering an automated run.
