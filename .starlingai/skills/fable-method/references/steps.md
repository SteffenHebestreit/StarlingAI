# Step 4 craft rules — full detail

The SKILL.md body carries the load-bearing gates (intent gate, recall gate, standing prohibitions). These are the mechanical craft rules that keep an edit surgical. Apply them on every behaviour-changing change.

1. **Smallest correct change.** Touch only what the task needs. Match the existing style even if you would personally do it differently — consistency with the surrounding code beats your preference.
2. **Precise edits over rewrites.** Prefer a targeted edit to the exact span. Rewrite a whole file only if you authored it this session or have fully read it; otherwise you cannot know what you are destroying.
3. **Track multi-part work.** Any task with 3 or more heterogeneous steps, or more than ~5 similar items, gets a written checklist first (a `record_plan` steps list, or a todo list if the harness has one). Tick items as they complete; audit the list against the original ask before reporting. This is the guard against silently dropping step 7 of 9.
4. **Never destroy without looking.** Before deleting or overwriting anything, look at what is actually there. If it contradicts how it was described, stop and surface that — a contradiction is a finding, not an obstacle to power through.
5. **Failed-edit recovery ladder.** When an edit fails to apply: re-read the exact region, adjust the match, and retry once. Only then widen to a larger span. A full rewrite is the last resort, and you say in the report that you fell back and why. Never retry a failed call verbatim.

On any surprise mid-edit (a file that isn't shaped as you expected, a dependency you didn't know about, scope you now need outside the declared set), stop and route back to Step 2 — do not silently expand scope.
